## 一、代理、认证与外部内容

| 编号 | 等级 | 问题和影响 | 修复与验证位置 |
|---|---|---|---|
| SEC-01 | 高 | loopback 代理没有请求鉴权，CORS 过度开放，网页或其他客户端可借桌面代理访问配置的服务。 | 进程启动时生成随机令牌，经 Tauri IPC 获取；每次请求校验令牌、精确 Origin 和 Host。前端 Axios、Fetch/SSE、刷新及登出统一接入。`proxy.rs`、`desktopProxy.ts` 及相应测试。 |
| SEC-02 | 高 | 固定代理端口被占用时仍可能继续启动，前端可能把远端凭据发送给占用者。 | 在桌面启动成功前同步绑定监听端口；绑定失败直接使初始化失败。新增真实占端口回归。 |
| SEC-03 | 中 | 收紧 CORS 后，简单使用 `Access-Control-Allow-Headers: *` 仍不能覆盖 Authorization 预检，认证请求会被浏览器拦截。 | 对允许的精确 Origin 返回实际请求的头列表；真实 OPTIONS 测试检查 Authorization、目标头和令牌头。 |
| SEC-04 | 中 | 全量缓冲上游响应使 SSE 在结束前不可见，并可能消耗大量内存；读取请求体失败被替换为空内容。 | 直接流式传递响应，限制请求体为 64 MiB，读取失败显式报错，设置 15 秒连接超时、300 秒读取空闲上限并清理逐跳头；没有整条流的总时限，兼容现有 120–180 秒批量操作。测试检查上游未结束时首个事件已到达。 |
| SEC-05 | 高 | 登出、刷新或异步请求跨越连接切换时可能使用另一连接目标或清除新会话。 | 捕获连接身份与修订号；凭据和目标来自同一快照，过期请求不覆盖新连接；登出先清理当前本地状态，再使用捕获的旧连接撤销旧会话。 |
| SEC-06 | 高 | 嵌入页面 URL 携带完整 JWT/管理密钥，原页面 query/hash 也可能随 `src_url` 外传。 | 移除这些敏感 URL 参数，仅允许 HTTP(S)，`src_url` 清除 query/hash；第三方页面使用自身认证。明确跨源的嵌入页面保留自身存储与登录，同源、非法和未知来源继续严格隔离。保留上游 CSP/X-Frame-Options，不为嵌入内容绕过安全策略。 |
| SEC-07 | 高 | 首页远端 HTML、外部 iframe 及开发配置注入存在脚本/标记注入面。 | HTML 通过 DOMPurify，iframe 使用 sandbox 和 no-referrer，Markdown 不再放行任意 iframe；配置序列化转义 `<` 及行分隔符；HTML 替换使用回调，避免 `$&` 被当作替换指令。 |
| SEC-08 | 中 | 二次认证保存密码路径没有始终遵守“记住密码”选择。 | 仅在用户选择记住密码时持久化；对应认证回归保留。 |
| SEC-09 | 高 | 支付返回链接、恢复的支付快照、OAuth 返回地址及部分下载和文档链接可直接进入导航，缺少对 `javascript:` 等可执行协议的拦截。 | 共享导航校验只接受 HTTP(S) 或明确安全的站内路径（`/`、`#/`）；覆盖支付创建与恢复、OAuth、扫码页查询参数、SDK 返回地址、备份下载、账号验证、版本、搜索结果和合规文档链接。微信扫码内容与固定格式的支付宝深链按原协议单独处理。 |

代理的目标校验拒绝非 HTTP(S)、URL 用户信息、query/fragment 和明显指向自身的地址。令牌仅用于本机代理鉴权，转发时移除，不能泄露给上游。HTTP 响应保留上游安全头；导航、iframe 和 WebSocket 使用正确的上游 URL，因为它们不能附加代理所需的自定义请求头。

### 账本迁移与历史修复边界

v16 新增的是检查点证据与归属信息，不能凭聚合金额重建过去没有保存的请求 ID。升级前已经封桶、且缺少请求级证据的历史漏项不能自动猜测补齐。旧检查点缺少归属快照时，程序保守保留未知历史粒度；不以“清理”为由删除无法证明归属的历史事实。

源库在封桶之后才修改已存在记录的内容，仍不自动追溯该历史更新；低于桶数值水位的任意历史回填也不自动重算。v16 边界键集合解决的是相同数值水位上晚到的新请求键。源库重建如果重新导出完全相同的旧事实、又缺少可信的跨世代身份，也不能仅凭小时总量判断是重放还是新使用量。修复保留事实，不承诺在缺少证据时推断精确去重。
