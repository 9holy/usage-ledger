# Usage Ledger 0.2.37 — Accuracy and Desktop Security

[English guide](../../README.md) | [简体中文说明](../../README.zh-CN.md)

Version 0.2.37 packages the three-round audit fixes for usage statistics, account attribution, persistent history, and desktop security. It retains the existing application identity and data locations.

| Mac with an Intel processor | [Usage-Ledger_0.2.37_macos_x64.dmg](https://github.com/9holy/usage-ledger/releases/download/v0.2.37/Usage-Ledger_0.2.37_macos_x64.dmg) |

Back up important data and fully quit the existing application before updating. On Windows, use **Quit Usage Ledger** in the tray, then run the new installer over the existing installation. Keep the existing data; do not uninstall or delete the ledger just to upgrade. On Mac, open the DMG for your processor and replace the application in `/Applications`, retaining the existing data directories. The Mac packages are separate native builds, not a universal binary.

Required database upgrades and evidence-based repairs run on startup. Original source logs remain unchanged. Historical classifications may change when retained evidence proves that an old classification was wrong; missing or conflicting evidence remains unknown. Sources and original quotes that have already been lost cannot be reconstructed from totals alone.

Check downloaded files against [SHA256SUMS.txt](https://github.com/9holy/usage-ledger/releases/download/v0.2.37/SHA256SUMS.txt). [BUILD-INFO.json](https://github.com/9holy/usage-ledger/releases/download/v0.2.37/BUILD-INFO.json) identifies the source commit, package hashes, and build evidence. Installation is manual: this release publishes no updater `.sig` files or `latest.json` automatic-update feed.

## Changes

1. **Account attribution follows request evidence.** Only uniquely matched requests contribute to a verified account total. Account switching, competing matches, revoked or corrected evidence, and reused source identities are handled consistently. Session creators and shared quota reset times no longer stand in for request ownership. Stable anonymous suffixes distinguish otherwise identical account labels.
2. **Usage totals and unknown values stay consistent.** Fix duplicate counting across log formats, collisions between sessions, out-of-order updates, and real-time output overcounting after a correction. Cumulative usage and records with no reliable request time retain their known totals without inventing exact request counts, dates, or output rates.
3. **Concurrent collection preserves persistent history.** Database upgrades, collector checkpoints, runtime evidence, quota snapshots, and weekly reports use consistent transactions. Fix missed late records, stale snapshots replacing newer data, rewound checkpoints, and history lost during source cleanup or reconstruction.
4. **Billing and quota forecasts require valid evidence.** Recheck subscription/API classifications, apply the same billing rules to historical backfills, and preserve original API quotes for reversals. Forecasts require verified account, quota, cycle, and observation-time agreement. Revoked, expired, conflicting, or incomplete evidence stops an unsupported current forecast.
5. **Invalid data produces an explicit error.** Reject invalid SQLite types, negative token counts, arithmetic overflow, and values outside the exact integer range. A failed ingestion batch rolls back without advancing its checkpoint or silently replacing unknown data with zero. Atomic file replacement protects existing ledger/configuration JSON from interrupted writes.
6. **Desktop connections and external content are hardened.** Authenticate the loopback bridge, validate its origin and host, bind its port before startup completes, and stream upstream responses. Keep credentials attached to their captured connection during switching. Remove secrets from embedded-page URLs, sanitize remote HTML, validate navigation protocols, and respect the saved-password choice.

### Release gates

The main [Repository checks workflow](../../.github/workflows/ci.yml) requires frontend tests, lint, builds, source policy, dependency checks, and the native headless suite, followed by native tests and packaging on Windows x64, macOS Apple Silicon, and macOS Intel. Windows package verification includes the executable architecture/version, silent installation, and isolated installed-app startup. Mac verification includes the executable architecture, ad-hoc signature structure, DMG integrity, and isolated packaged-app startup.

Only a successful `main` run with every required job passing may publish the versioned Release and its three installers. `fix/**` runs build review artifacts without publishing. The separate `test/macos-*` workflow remains a Mac preview build and does not publish a Release. Consult the actual Actions run linked by `BUILD-INFO.json`; defining these gates does not claim that a pending run has passed.

## Signing and validation limits

Windows packages do not have an Authenticode publisher certificate and may display **Unknown Publisher**. Mac packages use ad-hoc signing without Developer ID signing or Apple notarization. macOS remains a preview target: macOS 13 is the configured minimum, while CI uses macOS 15. The universal build, macOS 13 execution, Finder/Dock interaction, complete GUI/3D rendering, and real-account/provider-bill reconciliation have not been manually accepted in this release process. An automated startup check covers the process and local bridge, not every desktop interaction.

Known incomplete source records remain explicitly partial, unknown, or unassigned. Reference costs and quota forecasts are not provider invoices. Existing skipped/ignored tests still need their original external-data or diagnostic conditions. Audit logs retain the known jsdom diagnostic and Vite large-chunk warnings; neither is hidden by the passing counts.

启动时执行必要的数据库升级和有证据的历史修复，不改写原始来源日志。证据证明旧分类有误时会重新核验；缺失或冲突保持未知，不能仅凭汇总恢复已经丢失的原始记录与报价。下载可用 `SHA256SUMS.txt` 校验，`BUILD-INFO.json` 提供源码提交、文件摘要和构建证据。本版只支持手动安装，不发布 updater `.sig` 文件或 `latest.json` 自动更新清单。

### 六组主要修复

1. **按请求证据划分账号。** 主账号统计只接纳唯一匹配的请求；修复账号切换、证据竞争、撤销、更正、来源身份复用与恢复。不再凭会话创建者或相同额度重置时间推测归属，重名账号增加稳定的匿名区分。
2. **统一统计和未知值口径。** 修复新旧日志重复计数、跨会话请求覆盖、乱序回退，以及修正请求后实时输出多算。累计记录和时间未知记录保留已知总量，不假装具有准确请求数、日期或速率。
3. **保护并发采集与持久历史。** 数据库升级、采集进度、运行时证据、额度快照和周报采用一致事务；修复晚到记录漏读、旧快照覆盖新数据、游标回退，以及来源清理或重建造成历史丢失。
4. **计费与预测要求有效证据。** 重新核验订阅/API 分类，历史回填使用正常计费规则，保留原 API 报价用于撤销。账号、额度、周期及观察时间必须一致；过期、撤销、冲突或不完整的证据不能支持当前预测。
5. **异常数据显式报错。** 拒绝错型、负 Token、算术溢出和超出精确整数范围的值；失败批次回滚，不推进进度，也不把未知值写成零。JSON 文件采用原子替换，避免写入中断破坏旧文件。
6. **加强桌面连接与外部内容安全。** 本地代理校验令牌、来源和 Host，启动前先绑定端口，保持流式响应；切换连接时凭据与目标来自同一快照。移除嵌入页面 URL 中的密钥，过滤远端 HTML 与不安全跳转，并遵守记住密码选项。

### 签名与使用边界

Windows 没有 Authenticode 发布者证书，可能显示**未知发布者**。Mac 使用 ad-hoc 签名，没有 Developer ID 签名或 Apple 公证，仍作为预览目标。配置最低系统为 macOS 13，CI 使用 macOS 15；默认通用包、macOS 13 实机、Finder/Dock、完整 GUI/3D 效果与真实账号/提供方账单核对尚未完成人工验收。自动启动验证不等于全部桌面操作均通过。
