## Changes

- **Platform quota readers follow the actual producers.** Cockpit adapters now cover persisted Trae platform identity, Zed plan usage in `user_raw`, Windsurf daily/weekly fields, Buddy/CN/WorkBuddy resources, Cursor reset timestamps and Qoder usage envelopes. Google summary pools retain their own timestamps and stale status, and desktop cache selection rejects known project mismatches and prefers the fresher supported observation. Legacy quota history joins only an unambiguous Google account.
- **Official Codex quota state remains complete.** Main and additional pools, exact window seconds, plan, credits, spend controls and availability flags retain separate meanings. Non-minute windows cannot collapse into one identity or become a seven-day financial period by rounding. Missing percentage windows do not remove independently reported credit/status information. An exhausted extra pool does not mark the main weekly pool exhausted. An explicit current main-pool restriction prevents continued-use forecasts and cached forecast writes even when a reported window still has capacity.
- **Read failures remain visible.** Failed quota operations do not become successful empty arrays. Same-source retained observations keep their original age and a stale/error status. A failed or delayed response cannot overwrite another connection or account's current result.
- **CPA management metadata is accurate.** The running server version comes from its response headers; `/latest-version` describes the latest release. A connection revision during a request or later conversion work invalidates that old batch. Source summaries do not borrow the new connection's identity.
- **Purchase profiles distinguish zero from missing data.** Invalid amounts, currencies, cycles and dates are rejected; an empty amount is not a free purchase. Failed profile reads cannot silently supply defaults and produce complete economics. A verified prior snapshot may remain explicitly stale within the same source. Existing independent cost formulas are preserved.
- **Sub2API access diagnostics cover the actual list.** API-key pagination no longer stops at page one. Page failures and limits retain partial status, and stale connection/key responses cannot populate a different selection. A malformed successful models response is not reported as a healthy model list.
- **History and finance protect account ownership and stored facts.** Duplicate-email accounts retain separate current values instead of sharing one historical amount. JSON history rejects invalid counters and non-finite values before writing. Finance queries and batch reads validate stored events and allocation totals, returning errors instead of panicking or emitting null amounts. A new finance filter does not display the previous filter's totals during loading or after failure.

The [completion report](../data-channel-completion-2026-11-07.md) lists actual HTTP, SQLite, JSON and local language-server paths and links to per-source evidence. [Finance details](../finance-data-contract-audit-2026-11-07.md), [Cockpit producer contracts](../cockpit-quota-production-contract-2026-11-07.md), [CPA coverage](../cliproxy-interface-coverage-2026-11-07.md) and [Sub2API extension boundaries](../sub2api-extension-contract-audit-2026-11-07.md) preserve the concrete findings and before/after counterexamples.

## Verification and limits

The frozen local candidate passed **3,608 frontend tests**, **621 headless native business tests** and **15 release/platform script tests**, plus repository lint, TypeScript checks, desktop frontend and web builds. The 11 existing frontend skips and 21 native ignored diagnostics retain their original requirements. No production or test source changed during the final gate sequence.

The publication workflow requires the full frontend and native business suites, type/build checks, lint, release-script tests, source-manifest integrity, dependency checks, native Windows/macOS tests, installer packaging and isolated startup verification. The run and platform receipts in `BUILD-INFO.json` are the evidence for the downloadable packages; a pending run is not a pass.

Source review and synthetic regressions do not establish that private deployments captured every request or that supplier invoices reconcile with actual purchases. Optional Sub2API backend extensions absent from the available source, unrecorded historical owners and closed client protocol variants remain explicitly identified. Antigravity transcripts and local language-server metadata are separate inputs; unknown cache semantics remain unknown rather than a fabricated exact cost.

Windows installers have no Authenticode publisher certificate. Mac installers use ad-hoc signing without Developer ID signing or notarization. Separate native Mac packages remain previews validated by CI on macOS 15; the configured macOS 13 minimum, universal packages, full GUI and real-account flows are not established by those checks. Existing diagnostic/real-data skips keep their original requirements.

## 中文说明

0.2.39 在已经发布的 0.2.38 之后，继续逐项追踪三端成本、用量监控、账号和本地账目的实际接口与日志生产代码。修正数据输入、身份、窗口和失败状态；**保留本项目自己的采购、摊销、损失、利润、回本及报价公式。**

### 主要修复

- **Cockpit 平台字段**：补齐 Trae 四个平台身份、Zed `user_raw` 中的 plan usage、Windsurf 日/周额度、Buddy/CN/WorkBuddy 资源、Cursor 毫秒重置时间、Qoder 数据封装。Google summary 的旧桶不会因其他数据更新而变成新观察；缓存选择拒绝已知项目冲突，并优先采用时间较新的有效观测。兼容历史只关联唯一可证实的 Google 账号。
- **官方额度**：主池、额外池、精确秒数、plan、credits、支出限制和可用状态分别保留。61 秒与 119 秒不能合并；604799 秒不能按四舍五入当作七天财务周期。只有余额/状态、没有百分比窗口的合法响应仍能展示；额外池耗尽不误伤主池。主池明确受限时，即使窗口仍有余量也不再生成继续消费预测或写入预测缓存。
- **失败状态**：额度读取失败不再静默变成空列表；同源旧值保留原时间并显示历史/失败。连接或密钥已改变时，晚到响应不能写到新选择上。
- **CPA 与采购档案**：运行版本来自响应头，和最新发行版分开。空金额不能当零采购；损坏或读取失败的档案不能用默认值计算完整利润，合法的显式零和可证明的同源旧档案继续保留。
- **Sub2API 接入面板**：完整读取 API key 分页，页失败或达到上限标为部分结果；手动模型诊断绑定发起时的连接/密钥，畸形 HTTP 200 不显示为健康。
- **历史与账目**：同邮箱多账号保留各自当前数值，不套用同一份旧金额；歧义历史保留原文件并停止错误写回。前后端同时校验 JSON 历史的计数、时间和金额。财务批次读取/查询补齐校验；切换账号或时间后不显示旧范围金额。

完整输入、字段、日志、账号与消费者矩阵，以及旧实现失败和修复后的验证记录，见[本轮核验报告](../data-channel-completion-2026-11-07.md)。其中明确区分当前生产者、兼容历史读取器、外部委托页面和缺失服务端实现，未把缺少源码的扩展说成已经核实的远端账目。
