## Changes

1. **Sub2API historical usage stays in the totals.** Deleted or missing account profiles no longer remove their recorded usage from economic summaries. Known facts remain visible; incomplete profiles or windows cannot produce a complete purchase total, margin or capacity forecast. Ops queries use the same captured start/end window, fixing an unsupported one-minute parameter that the official server interpreted as an hour. Degraded HTTP 200 quota responses now remain errors or historical observations rather than fresh successful quotas.
2. **CPA history follows recorded evidence.** Primary and secondary slots are not mislabeled as fixed five-hour or weekly windows. Same-second records use their persisted order. Current auth-file owners and refresh timestamps no longer rewrite historical slot identity or last-use evidence. Partial token classification preserves the authoritative total and known subtotals without inventing a complete quote. Provider protocol names alone do not prove an official supplier.
3. **Cockpit source formats and identities are explicit.** The reader follows current, legacy, development and absolute custom data-directory rules. Nullable prices stay unknown; exact zero remains zero. Source price versions stay attached to their actual price group. Native quota formats preserve platform-specific percentage direction, absolute counts, time units and window presence. Plaintext account indexes can link encrypted details to uniquely attributable cache snapshots; duplicated email is not sufficient ownership evidence.
4. **Independent sources do not share retained usage or cost identities.** Independent CPA/Cockpit stores use stable source identities throughout account/profile/finance scope. Cockpit JSON history and persistent usage/checkpoints are separated by physical source; aliases of one physical store remain the same scope. Background ingestion captures one physical source and derives its input paths and destination from that same identity. Read errors and source switches cannot be interpreted as a fresh empty ledger and written over existing history.
5. **Usage-monitor quotas report failures honestly.** The quota read command uses a consistent transaction. Official Codex failures and invalid payloads are isolated by account, keep the original observation time and clear on verified recovery. Nullable or changed-duration windows preserve their history without staying current. Cockpit errors remain local to the affected account/source, including after changing roots.
6. **Managed sessions and financial validation are complete within the supported contract.** Codex discovery reads Cockpit's persisted `userDataDir`, with explicit partial errors for malformed entries. Own-ledger paths cannot enter upstream-owned current/legacy/dev/custom directories or aliases. Cross-account currency totals and lifetime amounts reject numeric overflow instead of serializing it as an unexplained null. No cost formula or exchange-rate policy is changed.

## Verification and limits

The [source audit](../data-channel-audit-2026-11-07.md) and its per-source reports record pinned upstream commits, endpoint/field mappings and counterexamples that failed before the fixes. The release workflow requires full frontend tests, lint, type/build checks, source-export integrity, dependency checks, the native business suite, native platform tests, installer packaging and isolated startup checks. A pending workflow is not a passing result; consult the run linked in `BUILD-INFO.json`.

Local pre-publication checks passed: 3,503 frontend tests (11 existing skips), 560 headless native business tests (21 existing ignored tests), 15 build-script tests, TypeScript, ESLint, and both desktop and web production builds. These counts do not replace the subsequent native Windows/macOS jobs or package checks recorded in `BUILD-INFO.json`.

The audit did not read private user account databases or reconcile actual supplier invoices. Upstream retention, partial logs, missing price data, ambiguous account ownership, optional Sub2API extensions and closed or unverified client formats retain explicit limitations. Antigravity transcripts without token evidence remain conversation discovery rather than invented usage. CPA authentication slots cannot prove historical account-owner lifetimes absent upstream evidence.

Windows packages have no Authenticode publisher certificate. Mac packages use ad-hoc signing without Developer ID signing or Apple notarization. Mac builds are separate architecture preview packages, tested by CI on macOS 15; the configured macOS 13 minimum and a universal package are not accepted by those checks. Automated installation/startup verification does not establish full GUI, Finder/Dock or real-account correctness. Existing diagnostic/real-data skips and ignored tests retain their original requirements.

## 中文说明

0.2.38 在已公开的 0.2.37 之后，针对 **Sub2API、CLIProxyAPI/CPA、Cockpit 与用量监控**逐一核验来源源码。本项目自己的采购、周期摊销和成本公式继续保留，本次修复输入事实、账号归属、时间窗口、完整性和实例隔离。

### 主要修复

- **Sub2API**：历史用量不因当前账号清单缺项而丢失；缺档案/不完整窗口保留已知小计并抑制完整盈利预测；修正一分钟 Ops 查询实际返回一小时范围；HTTP 200 的额度降级响应不再伪装成功。
- **CPA**：主/次额度窗口不再硬标 5 小时/7 天；按持久 ID 处理同秒记录；历史认证槽不被当前 owner、套餐或刷新时间重写；分类不完整时保留真实总量，不给完整报价；兼容协议名称不等于官方供应商证据。
- **Cockpit**：对齐新旧、开发及显式数据目录；区分空价格与真零价；正确关联价格组和版本；读取各平台原生额度字段、百分比方向和时间单位；同邮箱多账号保留歧义，不重复归属。
- **实例与账目**：独立来源的账号/成本档案/财务 scope 分开，Cockpit JSON 历史和 SQLite 用量/采集进度也分开。旧 legacy 物理根保留已有默认账目；独立 modern/custom/dev 根不会认领旧默认账本，目录别名仍属于同一个实际来源。后台采集用同一次捕获的来源身份选择源库和目的账本。读取失败或加载时切换来源不再被当作空账本覆盖写回。
- **用量监控**：额度响应使用一致读取事务；官方查询失败按账号隔离，旧值保留原时间并标历史；空窗口、换时长和恢复均正确处理；Cockpit 某账号或某来源失败不会污染其他账号或另一来源。
- **数据保护**：修正托管 Codex 实例的 camelCase 路径字段；自己的账本不能落到上游管理的目录及别名内；跨账号/终身金额溢出明确报错，不改成本公式。

推送前已完成的本地检查：前端 3503 项通过（11 项原有跳过），原生业务 headless 560 项通过（21 项原有 ignored），构建脚本 15 项通过，TypeScript、ESLint、桌面和 Web 生产构建均通过。实际 Windows/macOS 原生与安装包检查以 `BUILD-INFO.json` 关联工作流为准。

完整结果见[核验报告](../data-channel-audit-2026-11-07.md)。源码契约和合成回归能验证实现，不能代替用户真实数据库与供应商账单的逐笔核对。日志已被删除、来源缺失、私有扩展未知、认证槽缺少历史 owner 等限制继续明确展示，Antigravity 无 token 证据时不会编造用量。
